# Surviving mutations ruled to be non-defects.
#
# A mutation survives when the suite stays green with the code changed.  Most of
# the time that means a test is missing.  Sometimes it means the mutation cannot
# change what the program does: the arm is unreachable from any manifest, the
# input it depends on is never populated in production, or the only observable
# difference is the wording of a warning that was already firing.  Those are
# equivalent mutants, and a report that lists them next to a real hole is a report
# that stops being read.
#
# So they are ruled here, once, by a person, with the reason in the tree where it
# can be argued with — rather than suppressed by a flag or a comment nobody sees.
# `scripts/check-mutation-coverage.py` prints a ruled survivor in its own section
# with this reason beside it; it never hides one.
#
# FORMAT — six tab-separated fields, one ruling per line:
#
#   key   the 16-hex id the gate prints under the survivor.  It is a hash of the
#         file, the function, the operator and the before/after text, so it
#         survives the file being edited above the mutation and it does NOT
#         survive the mutated code itself changing.  That is the direction you
#         want: rewrite the code and the old ruling stops applying.
#   path
#   function
#   operator
#   date  when it was ruled, YYYY-MM-DD
#   reason  one line, ending in why the mutation cannot change behaviour
#
# A ruling is not a way to make the job quiet.  If you cannot write the reason in
# one line, the survivor is probably a missing test.
#
# ON TRY_DEFAULT SPECIFICALLY, because the first ruling written against one here was
# wrong and had to be withdrawn.  `expr?` folded to `expr.unwrap_or_default()` does
# not stop at the failure and report it differently -- it CONTINUES, and the default
# becomes an input to whatever the next line does with it.  An empty PathBuf handed to
# a subprocess, a zero hash compared for equality, an empty Vec written to a file, a
# None where a caller reads Some as consent.  So a TRY_DEFAULT ruling has to enumerate
# what the DEFAULT VALUE is then consumed by, not what error the program eventually
# reports.  The withdrawn one reasoned to the eventual message and missed that
# `uv run --script ""` executes <cwd>/__main__.py and EXITS 0: a step that failed,
# reported as a success, running whatever is in the Protocol directory.  It also
# asserted a shared retryability the two spellings did not share.  If you cannot list
# the consumers, you have not established equivalence -- you have established that you
# stopped reading at the `?`.
